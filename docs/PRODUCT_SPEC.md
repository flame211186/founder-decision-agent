# 产品规格

版本：0.1  
状态：核心 v1 范围已由用户确认，beta 验证进行中  
最后更新：2026-07-28

## 1. 产品结构

产品由三个逐步增强的模式组成。

### 1.1 单想法评估

输入一段自然语言想法，系统进行：

1. 想法重述与边界确认；
2. 阶段识别；
3. 信息缺口识别；
4. 必要时提出少量高价值澄清问题；
5. 快速初判或联网深度研究；
6. 多维分析与反方审查；
7. 输出结论、全面报告和现实行动计划。

### 1.2 个人适配评估

用户可以建立身份模板，报告不只判断“这是不是好想法”，还判断“它现在是否适合你”。

身份模板包括：

- 所在地区和可服务市场；
- 当前身份、行业和角色；
- 技能、作品和领域经验；
- 可触达用户、分发渠道和人脉；
- 每周可投入时间；
- 可投入资金和生存期；
- 团队与潜在合作资源；
- 风险承受能力；
- 希望得到的结果：学习、现金流、可持续小生意或风险投资型公司；
- 工作方式与不愿接受的生活代价；
- 伦理边界和不进入的行业；
- 历史项目、结果和已获得证据。

用户不填写模板也能使用；系统应渐进式询问，而不是用长表单阻止首次体验。

### 1.3 想法组合与个人洞察

当用户积累多个想法后，系统提供：

- 主题、目标人群、问题类型和商业模式聚类；
- 想法之间的互补、重复和冲突；
- 专长、资源优势和独特洞察信号；
- 反复出现的盲点与回避行为；
- “总想做大而不验证”等过程性模式；
- 基于证据的个人创业/产品 thesis；
- 下一阶段应该主动寻找的问题类型；
- 优先级矩阵与有限资源分配建议。

系统不得用心理诊断口吻给用户贴人格标签。个人洞察必须引用用户的具体想法和行为证据，允许用户纠正。

## 2. 输入

### 2.1 最小输入

只要求一段自然语言：

> 我想做一个能把零散想法整理成行动计划的应用。

系统从最小输入开始，不要求用户预先掌握商业术语。

### 2.2 可选输入

- 想解决的问题；
- 目标用户；
- 当前替代方式；
- 产品或服务形态；
- 为什么是现在；
- 已做过的验证；
- 用户、收入、留存或访谈数据；
- 价格与商业模式；
- 竞品；
- 获客方式；
- 团队与资源；
- 地区、行业和监管环境；
- 用户希望 Agent 重点挑战的问题；
- 身份模板；
- 相关文档、链接或数据。

### 2.3 澄清策略

系统不一次提出十几个问题。每轮优先询问最多三个“最可能改变结论”的问题。

允许用户选择：

- 直接按当前信息评估；
- 回答问题后再评估；
- 先生成快速报告，再逐步深化。

## 3. 输出层级

### 3.1 屏幕首屏摘要

必须能在短时间内读懂：

- 阶段性结论：推进 / 先验证 / 重构 / 暂存 / 停止；
- 结论置信度：高 / 中 / 低；
- 最有价值的一点；
- 最大风险；
- 现在最该做的一件事；
- 该项目属于生活方式生意、可扩张生意、风险投资候选或尚无法判断。

### 3.2 全面报告

标准报告包含：

1. 报告范围、评估日期、研究模式和信息完整度；
2. 一句话结论与执行摘要；
3. 想法重述和当前阶段；
4. 用户问题：严重度、频率、已有替代和未满足需求；
5. 目标客户与最小切入人群；
6. 解决方案、价值主张和产品行为变化；
7. Why now、市场变化与时机；
8. 市场潜力与可触达市场，不伪造精确 TAM；
9. 竞品和间接替代；
10. 差异化、切入点和可能的长期优势；
11. 商业模式、价格、单位经济性和现金需求；
12. 分发、销售和 go-to-market；
13. 技术、运营、法律、伦理和监管可行性；
14. 创始人/提出者适配度；
15. 风险投资适配度与可能的投资人疑问；
16. 牛市、基准、熊市三种情景；
17. 支持论点与反对论点；
18. 关键未知项和可能推翻结论的证据；
19. 改进版本、相邻机会和必要时的重构方向；
20. 7/30/90 天验证计划；
21. 每一步的时间、资金、资源输入和预期产出；
22. 继续、转向或停止的检查点；
23. 融资准备度、下一个融资里程碑和所需材料；
24. 事实、推断、假设、未知和引用清单。

行动章节必须先声明处置姿态：

- `active_validation`：允许执行明确实验；
- `parked_watch`：停止主动实验，只处理存量责任并观察重启条件；
- `stop_and_close`：不再验证当前想法，只执行停止、关闭和风险控制。

不能在首屏给出“暂存”或“停止”，又在正文继续要求用户做 7/30/90 天产品实验。

### 3.3 机器可读输出

所有报告同时生成版本化 JSON，至少支持：

- 其他应用渲染；
- 报告版本对比；
- 想法组合分析；
- 评测；
- 导出；
- API 集成。

自然语言报告由结构化结果渲染，不能成为唯一数据源。

## 4. 结论语义

- **推进**：现有证据支持进入下一阶段，但不表示最终成功。
- **先验证**：存在潜力，当前关键事实不足；先执行指定实验。
- **重构**：底层问题可能有价值，但当前用户、方案、切入点或商业模式不成立。
- **暂存**：想法可能成立，但当前时机、资源或个人匹配度不足。
- **停止**：存在当前无法合理绕过的致命约束，继续投入的机会成本过高。

每个结论必须同时包含：

- 为什么；
- 基于哪些证据；
- 哪个新证据会让结论改变；
- 当前结论具体授权的下一步；
- 该结论明确不代表什么，例如“推进不等于融资或扩团队”；
- 下一次复评时间或条件。

处置约束：

- 推进、先验证和重构必须至少包含一个与当前授权范围一致的主动实验；
- 暂存不包含主动实验，必须给出重启触发条件和存量责任；
- 停止不包含当前想法的继续实验，必须给出关闭动作；
- 停止后的相邻方向必须使用新的想法身份重新评估，不能把换名后的原方案伪装成改进。

## 5. 不同类型价值必须分开

报告至少独立判断：

- 问题/用户价值；
- 商业可持续性；
- 风险投资适配度；
- 对当前用户的个人适配度；
- 社会、伦理或监管风险。

例如，一个年收入潜力有限但很适合独立工作者的产品，不应因为“不够 VC 规模”而被判为无价值。

## 6. 研究模式

### 快速模式

- 主要依据用户输入和通用框架；
- 明确声明未完成外部事实核验；
- 用于想法早期筛选；
- 成本和等待时间较低。

### 深度模式

- 使用联网搜索和可配置数据源；
- 优先获取原始资料；
- 保存来源、访问日期和证据摘录；
- 对市场、竞品、监管和融资路径进行事实核验；
- 用于准备重大投入或对外沟通前。

## 7. 融资模块边界

系统可以：

- 判断是否适合 VC、天使、众筹、贷款、补助、自筹或收入融资；
- 指出投资人通常会追问的证据；
- 生成融资准备清单和材料提纲；
- 解释常见融资工具并链接权威材料；
- 按地区提示需要法律和财务专业人士复核。

系统第一版不可以：

- 保证融资；
- 推荐具体证券交易；
- 自动公开招揽投资；
- 自动发送融资邀约；
- 将通用法律信息包装成适用于用户的法律意见。

## 8. 行业扩展

通用核心保持一致，行业包只增加：

- 行业特有问题；
- 关键指标；
- 数据源；
- 监管检查；
- 常见商业模式；
- 专家评测案例；
- 报告附加章节。

预期行业包：

1. B2B SaaS；
2. 消费产品；
3. 市场平台；
4. 内容与创作者业务；
5. 专业服务；
6. AI 原生产品；
7. 硬件；
8. 深科技；
9. 医疗、金融等强监管行业。

不在第一版同时实现所有行业包。
