# 评估方法

版本：0.1  
状态：方法草案，需通过样例评测和用户确认  
最后更新：2026-07-28

## 1. 方法目标

评估方法追求的是：

- 完整但不泛化；
- 有判断但不过度自信；
- 对关键变量敏感；
- 能清楚解释；
- 能指导现实动作；
- 能用评测案例不断校准。

它不追求用一个数字预测创业成功率。

## 2. 评估流程

```text
自然语言输入
  → 想法规范化
  → 阶段与类型识别
  → 信息缺口排序
  → 必要的澄清
  → 研究计划
  → 外部证据采集（深度模式）
  → 分维度评估
  → 最强支持论点
  → 最强反对论点
  → 证据与引用验证
  → 置信度校准
  → 结论与行动计划
  → 用户纠正与版本迭代
```

评估阶段采用“支持者—怀疑者—综合者”三视角，但它们是可测试的分析阶段，不默认实现为三个自治 Agent。

## 3. 项目阶段

- **S0 想法**：只有概念和少量假设。
- **S1 问题发现**：有访谈、观察或行为证据。
- **S2 方案验证**：有原型、意向或早期试用。
- **S3 早期牵引**：有真实使用、留存、付费或合同。
- **S4 可重复增长**：存在可复制获客和经济模型。

不同阶段使用不同权重和证据标准。S0 的核心输出应是验证路线，而不是伪造收入预测。

## 4. 核心维度

每个维度采用 0–5 的有锚点评分，但分数只是压缩表达，解释和证据优先。

### D1 问题强度

- 问题是否真实；
- 严重度、频率和持续性；
- 用户是否已经付出时间、金钱或风险解决；
- 不解决的代价。

### D2 用户与切入点

- 目标用户是否具体；
- 是否存在可优先服务的窄人群；
- 用户是否可触达；
- 购买者、使用者和受益者是否一致。

### D3 方案价值与行为变化

- 方案是否显著优于现有替代；
- 是否更快、更便宜、更可靠或创造新能力；
- 是否足以改变用户行为；
- 产品承诺是否可验证。

### D4 时机

- 技术、政策、成本、分发或行为发生了什么变化；
- 为什么以前不成立而现在可能成立；
- 时机窗口会持续多久。

### D5 市场与扩张

- 初始可触达市场；
- 相邻扩张路径；
- 市场增长和结构；
- 是否适合用户想要的小生意或 VC 规模。

### D6 竞争、替代与差异化

- 直接竞品、间接替代和“不做任何事”；
- 差异是否具体；
- 切入点是否容易被复制；
- 长期优势可能来自数据、分发、网络、品牌、成本、流程嵌入或监管资质中的哪一项。

### D7 商业模式与经济性

- 谁付钱、为什么付钱；
- 定价和价值交换；
- 毛利、服务成本、回收周期和现金周期；
- 在合理规模下能否成为可持续生意。

### D8 分发与销售

- 第一批用户从哪里来；
- 创始人是否拥有渠道优势；
- 获客路径是否与客单价匹配；
- 是否存在可复制的增长机制。

### D9 可行性

- 技术、数据、运营和供应链难度；
- 时间、成本和关键依赖；
- 监管、法律、伦理和安全风险；
- 最小可验证版本能否低成本完成。

### D10 提出者适配度

- 领域洞察、技能和可信度；
- 用户访问能力和人脉；
- 可投入时间、资金和团队；
- 动机与长期耐受度；
- 生活目标、风险偏好和项目要求是否匹配。

### D11 牵引与学习速度

- 已获得的用户、行为、付费、留存或合同证据；
- 实验速度和每轮学习质量；
- 是否根据反证修正过想法；
- 只在有相应阶段数据时计入。

### D12 资本与回报形态

- 到下一个价值拐点需要多少资本；
- 是否资本高效；
- 适合自筹、收入融资、补助、天使还是 VC；
- 潜在回报是否与资金类型匹配。

## 5. 评分规则

### 5.1 锚点

- 0：存在直接反证或致命问题；
- 1：非常弱，主要依赖未说明假设；
- 2：有合理叙事，证据不足或结构性问题明显；
- 3：中性/初步成立，仍有关键未知；
- 4：较强，有多项相互支持的证据；
- 5：在当前阶段具有异常强、可复核的证据。

### 5.2 禁止事项

- 不把缺失信息自动当作负面事实；
- 不把创始人的热情当作用户需求证据；
- 不把大 TAM 当作可获客性证据；
- 不把“AI + 行业”当作差异化；
- 不使用未验证的精确成功概率；
- 不用一个总分掩盖致命风险。

### 5.3 致命约束

即使平均分较高，以下情况也可能触发“重构、暂存或停止”：

- 核心问题没有用户行为证据且无法低成本验证；
- 必需数据或许可在现实中无法获得；
- 单位经济性在合理情景下仍不可成立；
- 监管或安全要求与团队资源严重不匹配；
- 方案依赖不可控平台且没有缓解路径；
- 用户明确目标与项目回报形态冲突；
- 存在更便宜、风险更低且同样能验证底层假设的替代路径。

## 6. 证据体系

每条关键主张标记为：

- **U：用户提供**；
- **E：外部证据**；
- **C：确定性计算**；
- **I：模型推断**；
- **A：情景假设**；
- **K：未知**。

外部证据记录：

- 来源 URL 或文件；
- 来源类型；
- 发布/更新日期；
- 访问日期；
- 支持的具体主张；
- 地区和适用范围；
- 是否存在冲突来源。

来源优先级：

1. 法律法规、监管机构、原始数据；
2. 公司官方材料、产品和定价；
3. 同行评审研究和可信行业数据库；
4. 高质量专业媒体和投资机构公开框架；
5. 论坛、社交媒体和用户评论；
6. 聚合文章和搜索摘要。

低优先级来源可以帮助发现线索，但不能独自支持高风险结论。

## 7. 置信度

置信度不等于项目成功概率。它表示“当前结论被现有信息支持的程度”。

置信度由以下因素组成：

- 信息覆盖度；
- 来源质量；
- 来源新鲜度；
- 多来源一致性；
- 关键数字可验证性；
- 结论对假设变化的敏感程度；
- 当前项目阶段。

报告必须说明：

- 哪些因素降低置信度；
- 哪三个信息最能改变结论；
- 获得这些信息的最低成本方式。

## 8. 情景与现实计划

涉及收入、成本、时间或市场时，默认输出：

- 熊市情景；
- 基准情景；
- 牛市情景。

每个情景必须列出假设，并使用确定性计算器生成结果。禁止在没有输入或来源的情况下输出貌似精确的五年财务表。

行动计划以“实验”组织：

- 要验证的假设；
- 最小动作；
- 预计时间；
- 预计现金成本；
- 所需用户/渠道/技能；
- 产生的证据；
- 成功阈值；
- 失败阈值；
- 下一决策。

但实验不是所有结论的默认动作。系统先选择处置姿态：

- `pursue`、`validate`、`reframe` → `active_validation`，至少一个被授权实验；
- `park` → `parked_watch`，不安排主动实验，记录存量责任和可观察重启条件；
- `stop` → `stop_and_close`，不安排当前想法实验，只列停止、关闭和风险控制动作。

对 `park` 强行安排实验会制造隐性继续投入；对 `stop` 输出牛市情景或增长实验会与结论直接冲突。只有在不复用致命机制的情况下，才可以把相邻方案建立为新的想法重新评估。

## 9. 多想法个人洞察方法

组合分析只根据用户已经输入的想法、选择和结果产生，不做临床心理或人格诊断。

分析维度：

- 反复选择的行业和用户；
- 问题驱动还是技术驱动；
- 想法范围和验证难度；
- 对产品、分发、销售、监管和经济性的关注偏差；
- 资源和能力复用程度；
- 反复出现但尚未利用的个人优势；
- 从想法到行动的转化率；
- 对反证的反应方式；
- 哪些判断来自具体证据，哪些只是弱模式。

每条个人洞察必须提供至少两个具体想法或行为作为依据；依据不足时标记为“待观察”。

## 10. 评测设计

### 10.1 数据集

- `golden_cases`：不同阶段、行业和质量的代表性想法；
- `counterfactual_pairs`：只改变一个关键变量，检查结论是否合理变化；
- `missing_information`：检查是否承认未知并提出正确问题；
- `adversarial_cases`：流行词堆叠、虚假 TAM、提示词注入、矛盾数据和高风险行业；
- `stale_fact_cases`：检查时间敏感事实是否更新；
- `portfolio_cases`：多想法聚类、优势与盲点分析；
- `regression_cases`：每个真实失败转成长期回归案例。

### 10.2 评测维度

- 事实与引用正确性；
- 不支持主张率；
- 数字可追溯性；
- 致命问题召回；
- 关键问题排序；
- 对反事实变化的敏感性；
- 重复运行的稳定性；
- 阶段适配；
- 行动计划可执行性；
- 报告完整性和简洁度；
- 对用户目标与资源的适配；
- 专家判断一致性。

### 10.3 人工评审

高判断正确性不能只靠模型评分证明。计划邀请创业者、产品负责人、天使或 VC 进行盲评，并记录分歧。

专家分歧不一定意味着 Agent 错误；系统应保留不同投资 thesis，并判断分歧来自事实、权重还是风险偏好。

### 10.4 发布质量门

阈值在基线评测完成后确定。发布前至少要求：

- 所有关键数字能追溯；
- 引用验证通过；
- 没有已知提示词注入导致的越权；
- 结构化输出通过 Schema 校验；
- 致命问题测试无高严重度漏检；
- 专家样例评审达到预先批准的标准；
- 公开限制和已知失败模式。

## 11. 反幻觉技术控制

- 研究结果先写入证据账本，再进入分析；
- 报告主张与证据建立显式映射；
- 搜索和网页内容按不可信输入处理；
- 数值使用专门计算工具；
- 模型输出强制 Schema；
- 事实验证器与报告生成步骤分离；
- 引用必须真正支持对应句子；
- 对未知项允许无答案；
- 保存模型、提示词、工具和来源版本；
- 对高风险领域加入人工复核提示；
- 线上反馈和失败自动进入回归候选，但需去除隐私。

具体失败编号、严重度与回归要求见 `FAILURE_TAXONOMY.md`。
