## 总体原则

每个阶段只在上一阶段质量门通过后开始。阶段门不是形式审查；如果样例暴露方法问题，应返回修改方法，而不是用更多提示词或代码遮盖。

用户要求一次完成完整开源 Agent，因此当前仓库已经形成 Phase 1–6 的窄实现切片。实现存在不等于质量门通过：Phase 0 的真实案例与专家评审仍然开放，稳定 `v1` 不能因后续代码已写而提前声明完成。

## Phase 0：定义问题与判断方法

目标：证明我们知道要构建什么，以及如何判断它是否做得好。

交付物：

- 项目宪章；
- 产品规格；
- 初版评估维度、证据与结论语义；
- 报告 Schema 草案；
- 10–20 个手工样例输入；
- 3–5 份人工撰写的目标报告；
- 失败分类和评测计划；
- 架构 ADR；
- 隐私与安全边界。

质量门：

- 用户确认产品定位和核心输出；
- 同一个想法能明确区分“项目价值、VC 价值、个人适配度”；
- 报告模板对至少三类想法有效；
- 已知哪些信息会改变结论；
- 技术选型由需求而不是偏好支持。

当前状态：方法、五档结构、专家盲评协议、实时重复/反事实工具、人工质量复核以及
隐私保守的同意/评审/统一证据审计已形成；真实案例与专家评审质量门仍进行中。

当前内部进度：

- 已建立 18 个案例矩阵；
- 已完成 5 份手工目标报告，覆盖全部 `pursue`、`validate`、`reframe`、`park` 和 `stop`；
- 五份报告覆盖 AI/open-source 产品、垂直 B2B SaaS、双边市场、身份反事实和敏感数据致命约束；
- 报告协议已区分主动验证、暂存观察和停止关闭，防止结论与行动矛盾；
- 全部通过当前 Schema 和交叉引用检查；
- 已建立专家盲评协议、结构化评审表和确定性记录验证器，但尚未执行真人评审；
- 已建立真实案例同意/去标识化 Schema 和验证器，但尚未收集真实记录；
- 仍缺真实用户案例、专家评审与用户方向确认。

## Phase 1：可执行的评估内核

目标：完成一个窄但真实的单想法评估闭环。

已确认交付形态：独立 npm 包 + CLI，二者共用同一评估核心。

范围：

- 自然语言输入；
- 阶段识别；
- 最多三项关键澄清；
- 结构化评估；
- 支持/反对论点；
- 五档结论；
- 7/30 天实验计划；
- Markdown + JSON 输出；
- CLI；
- 无联网快速模式。

明确不包含：

- 多想法个人洞察；
- 自动联网研究；
- 所有行业；
- 网页产品；
- 自动融资联系。

质量门：

- Schema 校验；
- 代表性样例通过人工评审；
- 关键变量改变时结论合理变化；
- 无依据数字和事实能被拦截；
- 从干净环境一条命令运行；
- 单元、集成和离线评测通过。

当前状态：代码、Schema、单元/集成/fixture 验证已实现；三次重复基线和两个单变量
反事实的可重复 BYOK 工具也已实现，但实时模型和人工报告质量验证待完成。

## Phase 2：证据研究与引用

目标：让市场、竞品、时机和监管判断建立在可复核证据上。

范围：

- 研究计划；
- 搜索与网页读取；
- 来源等级；
- 证据账本；
- 主张—来源映射；
- 引用验证；
- 来源日期和冲突处理；
- 研究缓存和可重放快照；
- 深度模式。

质量门：

- 关键事实均可追溯；
- 引用真正支持对应结论；
- 时效性案例能识别过期资料；
- 网页提示词注入不能改变系统权限；
- 研究失败时安全降级为未知；
- 费用和延迟有可配置上限。

当前状态：OpenAI web search、来源 allowlist、访问日期字段、角色复核、预算和最多
12 条外部事实的确定性人工抽样清单已实现；引用语义蕴含、缓存/重放和过期事实人工
评测未完成。

## Phase 3：身份模板与个人适配

目标：回答“它是不是好想法”之外的“它是否适合现在的你”。

范围：

- 渐进式身份模板；
- 时间、资金、技能、渠道和风险约束；
- 不同目标类型：学习、现金流、小生意、VC；
- 资源差距与获取计划；
- 本地保存、导出、删除。

质量门：

- 同一想法在合理不同身份下产生可解释差异；
- 不把身份特征变成刻板印象；
- 用户可纠正推断；
- 敏感数据最小化并可删除。

当前状态：版本化身份资料、SQLite 保存/导出/删除和 founder-fit 输入已实现；真实身份反事实与用户纠正测试待完成。

## Phase 4：多想法组合与个人洞察

目标：从想法历史中发现可验证的优势、盲点和长期方向。

范围：

- 想法聚类；
- 跨想法对比；
- 资源复用；
- 重复盲点；
- 个人 thesis；
- 优先级与机会成本；
- 想法版本演化。

质量门：

- 每项个人洞察有具体证据；
- 数据不足时明确“待观察”；
- 用户能查看、纠正和删除；
- 不产生心理诊断；
- 组合结论对新增或删除想法具有合理变化。

当前状态：确定性聚类、证据阈值、优先级和无心理诊断边界已实现；真实用户纠正与长期演化待完成。

## Phase 5：融资准备与行业包

目标：在项目达到相应阶段后，提供合规边界内的融资准备支持。

范围：

- 融资适配度；
- 里程碑与资金用途；
- 投资人问题清单；
- 材料提纲；
- 不同资金类型；
- 地区性权威资料链接；
- 首批 1–2 个行业包。

质量门：

- 不把融资当作所有项目默认目标；
- 法律和证券相关内容标注地区和来源；
- 无自动公开募资或无确认外联；
- 行业包有领域评测案例和专家复核。

当前状态：融资字段、美国/中国大陆官方入口、B2B SaaS 与 AI-native 包已实现；法域/行业专家复核待完成。

## Phase 7：接入想法收集产品

目标：保持独立 Agent 边界，通过稳定接口接入目标产品。

目标产品已由用户确认为 `/Users/frame/Documents/lmao app`。当前只读技术快照为 TypeScript/Cloudflare/Drizzle，但用户已决定部署平台保持中立；Cloudflare 只作为可选适配器。在 Phase 7 获得明确修改授权前继续保持只读。

范围取决于目标产品：

- 身份和权限；
- 异步任务；
- 运行状态；
- 报告渲染；

- 用户数据隔离；
- 费用配额；
- 删除和导出；

质量门：

- 独立 Agent 仍可单独运行；
- 产品不直接依赖内部提示词；
- 契约测试覆盖 API；
- 数据权限和删除流程端到端验证；
- 集成不覆盖或破坏现有用户工作。

## 每阶段固定工作方式

1. 确认当前风险和问题；
2. 写出可验证规格；
3. 用户确认真正影响产品的决定；
4. 构建最小垂直切片；
5. 用样例和失败案例验证；
6. 记录证据、分歧和遗留问题；
7. 通过质量门后才进入下一阶段。
