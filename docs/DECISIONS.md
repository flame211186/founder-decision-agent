### DEC-004：未来集成目标为 lmao app

状态：用户于 2026-07-28 明确确认。

决定：

### DEC-005：部署平台保持中立

状态：用户于 2026-07-28 明确确认。

决定：

- Agent 核心不绑定 Cloudflare、AWS、Vercel 或其他单一云平台；
- `lmao app` 当前使用 Cloudflare 只能作为适配背景，不能变成 Agent 的运行前提；
- 本地运行、普通 Node.js 服务和其他云部署必须能够复用同一领域核心与报告协议；
- Cloudflare D1/R2 只作为未来可选适配器；
- 更换部署平台不得要求重写评估方法、核心工作流或公共 Schema。

### DEC-006：独立开源首发采用 npm 包 + CLI

状态：用户于 2026-07-28 明确接受。

决定：

- 陌生用户可以通过 npm 安装；
- 用户可以直接在命令行输入想法、读取文件并生成 JSON/Markdown 报告；
- TypeScript/JavaScript 项目可以通过稳定的库 API 调用同一核心；
- CLI 与库 API 必须共用领域逻辑，不能维护两套判断实现；
- Docker 可以在开源产品化阶段补充，但不是 Phase 1 的首发前提；
- npm + CLI 只决定发布与使用形态，不改变部署平台中立原则。

### DEC-007：产品定位、用户和首次体验

状态：用户接受推荐方案。

决定：

- 正式定位为“证据校准的创始人想法决策系统”，投资人只是分析视角之一；
- 首发服务独立工作者、个人开发者/创作者及 idea 到 pre-seed 的个人或小团队；
- 最小输入只需自然语言想法；
- 报告最多提出三个高信息量澄清问题，用户可以通过 `answers` 补充后重评；
- 硬件、医疗、金融、深科技和强监管业务只能识别风险，不承诺专业判断。

### DEC-008：五档结论和严格处置

状态：用户接受推荐方案。

决定：

- 结论固定为 `pursue`、`validate`、`reframe`、`park`、`stop`；
- 前三者必须使用 `active_validation` 并至少给出一个实验；
- `park` 必须使用 `parked_watch`、零主动实验并给出重启条件；
- `stop` 必须使用 `stop_and_close`、零当前想法实验并给出关闭动作；
- 移除致命机制的相邻方案必须以新 idea ID 重评，不能隐藏延续停止项目。

### DEC-009：显式 TypeScript 工作流

状态：用户明确选择“显式 TypeScript 工作流”。

决定：

- 首版使用可检查的 TypeScript 工作流，不依赖 LangGraph、Mastra、CrewAI 或其他通用 Agent 编排框架；
- 核心通过 `ModelAdapter` 与 `StorageAdapter` 解耦提供商和存储；
- 快速、深度、角色分析、验证、修复和预算均为显式阶段；
- OpenAI Responses API 是首个默认适配器，但不是领域依赖；
- 本地模型和其他提供商在后续有需求和评测证据时通过适配器加入；
- CLI、SDK、MCP 和 Node HTTP 复用同一核心。

### DEC-010：联网、模型次数和费用

状态：用户接受推荐方案，并明确默认值后期可调。

决定：

- 快速模式不联网，默认最多 2 次模型调用、0 次搜索、2 分钟；
- 深度模式显式联网，默认最多 8 次模型调用、10 次搜索、15 分钟；
- 上述均为用户可覆盖的默认上限，不是固定次数；
- 默认 OpenAI 模型为快速 `gpt-5.6-terra`、深度 `gpt-5.6-sol`，可通过环境或 SDK 覆盖；
- 使用 BYOK：OpenAI 模型和搜索费用由 API Key 所属用户账户承担；
- 本项目不代付、不加价、不保存 API Key；
- 稳定版模型默认值必须由真实评测支持，不因新模型发布自动切换。

### DEC-011：本地优先数据与隐私

状态：用户接受推荐方案。

决定：

- SQLite 是独立版默认历史与身份资料存储；
- 单次评估可 `--no-persist`；
- 历史和身份资料支持读取、导出和删除；
- API Key 只从环境或构造参数注入，不进入报告、manifest、事件或数据库；
- OpenAI Responses 请求设置 `store: false`，同时明确这不等于覆盖提供商全部 abuse-monitoring/data-control 政策；
- 敏感 MCP 保存/删除要求显式 `confirm: true`，CLI 删除要求 `--yes`。

### DEC-015：SQLite 使用 Node 内置驱动

状态：发布前可逆实现决定。

决定：

- 保持 `SqliteStorage`、数据库文件格式和 `StorageAdapter` 公共契约不变；
- 默认 SQLite 适配器使用 Node 内置 `node:sqlite`，不再依赖需要原生安装脚本的 `better-sqlite3`；
- 最低 Node 版本继续为 `22.14.0`，CI 同时验证最低版本和当前 Node 24；
- Node 22.14 的 `node:sqlite` 会显示实验性警告，公开限制中必须披露；Node 24 为推荐运行版本；
- 如果后续稳定性或性能评测证明内置驱动不满足要求，应在不改变领域核心的前提下增加可选存储适配器，而不是重新引入隐式安装脚本。

理由：

- npm 已开始记录依赖安装脚本审批，并计划默认阻止未经消费者项目批准的脚本；
- 全局 CLI 用户无法通过项目 `package.json` 继承本项目对原生依赖脚本的批准；
- Node 内置驱动避免原生编译、预构建二进制下载和平台 ABI 差异，同时能直接读取现有标准 SQLite 文件。

## 历史 ADR 建议

ADR-001 至 ADR-011 的最终决定已由 DEC-007 至 DEC-014 固化。以下内容保留为选择背景，不再是当前阻塞项。

### ADR-001：产品定位

推荐：**证据校准的创始人想法决策系统**。

不推荐把公开定位写成“AI 投资人预测器”，原因：

- 早期项目不可被可靠地绝对预测；
- 过度强调投资人会贬低适合独立工作者的小生意；
- 容易诱导虚假确定性。

历史确认项：

- 是否接受推荐定位；
- “投资人视角”作为核心分析视角，但不是产品唯一价值标准。

### ADR-002：五档结论

推荐：

- 推进；
- 先验证；
- 重构；
- 暂存；
- 停止。

用户已确认保留明确的“停止”结论。

### ADR-003：第一版目标用户

推荐先聚焦：

- 独立工作者；
- 个人开发者/创作者；
- idea 到 pre-seed 的个人或小团队；
- 数字产品、服务、内容和轻量 AI 产品。

硬件、医疗、金融和深科技先能识别风险，但不承诺深度专业判断。

### ADR-004：首次体验方式

推荐：

- 最小输入只需自然语言想法；
- 先重述；
- 每轮最多三个高信息量问题；
- 用户可跳过问题并接受低置信度报告。

### ADR-005：联网研究默认值

推荐：

- 快速模式默认不联网；
- 深度模式由用户显式选择；
- 联网时保存证据来源和访问日期；

### ADR-006：身份资料与存储

推荐：

- 本地优先；
- SQLite 作为独立版本默认存储；
- 用户可关闭历史、导出和删除；
- 对外服务版本再加入账户隔离与远端数据库。

### ADR-007：技术路线

已确认：

- `/Users/frame/Documents/lmao app` 是最终要接入的想法收集产品；
- 其当前技术形态为 TypeScript + Cloudflare + Drizzle，并具备 D1/R2 绑定；
- 独立开源能力仍优先于集成。
- 用户要求部署平台保持中立，不把 Cloudflare 设为长期前提。
- 独立开源首发采用 npm 包 + CLI。

已批准并实现的方向：

- 采用 TypeScript 作为 Phase 1 核心领域与工作流语言；
- 先发布独立 npm 包和 CLI；
- 通过存储端口支持本地 SQLite，并让 D1、PostgreSQL 等远端存储成为可选适配器；
- 通过模型、搜索和追踪端口避免绑定单一供应商；
- `lmao app` 未来只依赖版本化 Schema、SDK 或 HTTP 接口，不直接依赖内部提示词；
- 核心包不得导入 Cloudflare 专用运行时或绑定；
- Python 只在后续评测或研究确有证据证明必要时引入，不在第一阶段维护双语言核心。

本地模型已延期为后续适配器，不是首发要求。

选择背景见 `ARCHITECTURE_PLAN.md §6`。

### ADR-011：结论与处置姿态

状态：已由 DEC-008 确认并实现。

推荐：

- `pursue`、`validate`、`reframe` 使用 `active_validation`，必须给出至少一个授权实验；
- `park` 使用 `parked_watch`，不继续主动实验，必须处理存量责任并给出重启条件；
- `stop` 使用 `stop_and_close`，不得继续验证当前想法，必须给出关闭和风险控制动作；
- 停止后的相邻方案如果移除了致命机制，应建立新的 idea ID 重新评估。

原因：

- 避免首屏说停止，正文却暗中鼓励继续投入；
- 避免把暂存变成没有期限的拖延；
- 让 API 和未来产品能区分实验、等待与关闭三种真实状态；
- 让用户清楚哪些动作被授权、哪些动作明确禁止。
