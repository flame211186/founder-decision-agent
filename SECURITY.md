# Security policy

## Supported versions

Security fixes are provided for the latest published beta or stable line. Pre-publication repository snapshots are not supported releases.

## Reporting

Do not include secrets, confidential ideas, founder profiles or exploit details in a public issue.

Use GitHub private vulnerability reporting for `flame211186/founder-decision-agent` when available. If it is not available, open a minimal public issue requesting a private contact channel without disclosing the vulnerability.

Include the affected version, impact, reproduction prerequisites and suggested mitigation. Reports involving remote code execution, credential exposure, cross-user data access, prompt/tool injection that causes external writes, or silent corruption of high-stakes conclusions receive priority.

## Boundaries

Model disagreement, poor business judgment or an unsupported factual claim may be a quality defect rather than a software vulnerability; report it with a synthetic reproduction and the relevant failure-taxonomy category. Never attach real private data.
